# API reference

Base URL: `http://localhost:8080/api`

| Method | Path | Result |
|---|---|---|
| GET | /health | API status and database mode |
| GET | /employees | All employees, newest database ID first |
| GET | /employees/{id} | One employee, or 404 |
| POST | /employees | Create employee; 201 plus Location header |
| PUT | /employees/{id} | Replace editable fields; 200 |
| DELETE | /employees/{id} | Delete record; 204, or 404 |

POST and PUT body (Postman → Body → raw → JSON):

```json
{
  "name": "Demo Employee",
  "email": "demo.employee@example.com",
  "department": "Engineering",
  "role": "Java Developer",
  "status": "ACTIVE",
  "joinedOn": "2026-01-10"
}
```

Status values: ACTIVE, ON_LEAVE, INACTIVE. Joining date must not be in the future. Required text must not be blank. Name/role max 100 characters, email max 160, department max 80. Email is stored in lowercase; duplicate addresses are rejected case-insensitively.

A successful response contains the same fields plus `id`. IDs are generated by the database and need not be consecutive after deletions or rejected inserts.

Duplicate response (409):
```json
{"message":"An employee with that email already exists."}
```

Validation response (400) example:
```json
{"message":"Please correct the highlighted fields.","errors":{"email":"Enter a valid email address"}}
```

Filtering, search, pagination and CSV are implemented in React over the fetched directory. For a large production workforce, add server-side pagination/filtering and authorization. This API is intentionally local and unauthenticated for the portfolio project.
